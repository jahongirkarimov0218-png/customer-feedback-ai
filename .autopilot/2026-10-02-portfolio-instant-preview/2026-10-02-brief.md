## 1. Задача 1: Внедрение функции мгновенного предпросмотра (Instant Preview)

Проблема:
Рекрутер или технический директор не хочет тратить время на ввод текста или ожидание запроса в пустом поле ввода. Если результат не виден сразу, конверсия портфолио падает.

Требования к реализации:
1. Интерактивный триггер:
   - Добавь рядом с кнопкой отправки (или непосредственно под основным заголовком) кнопку быстрого действия: «Jonli namunani ko'rish ->» («Посмотреть живой пример ->»).
   - Кнопка должна обладать тактильным откликом по физике Emil Kowalski (`active:scale-[0.98] transition-transform duration-100 ease-out`).
2. Поведение при клике:
   - В 1 клик без задержек и ожидания сети подставляет эталонный мок-датасет в состояние приложения.
   - Мгновенно отображает полный рабочий дэшборд: матрицу проблем с фильтрами P0/P1/P2, NPS/Health Score, 3 ключевых инсайта, модальное окно с цитатами и Action Bar с инженерной рекомендацией.
   - Выполняет плавный программный скролл (`behavior: 'smooth'`) к блоку результатов, фокусируя пользователя на аналитике.
3. Сохранение функциональности:
   - Ручной ввод текста и пресеты индустрий остаются полностью рабочими.
   - При наличии сгенерированных результатов кнопка позволяет мгновенно сбросить или перезагрузить демонстрационные данные.

## 2. Задача 2: Позиционирование и инженерный UVP (Unique Value Proposition)

Проблема:
Обычные аналитики отзывов выдают поверхностную статистику в духе «70% позитива, 30% негатива», которая не несет пользы для продуктовой разработки. Сила этого проекта — трансформация сырого шума напрямую в инженерный бэклог (Linear / Jira).

Требования к копирайтингу и элементам:
1. Микро-бейдж над заголовком (без эмодзи):
   - Добавь лаконичный бейдж в стиле Linear/Vercel над Hero H1:
     `[Не просто тональность: готовый бэклог для Linear и Jira]`
     (на узбекском для текущей локализации: `[Shunchaki sentiment emas: Linear va Jira uchun tayyor backlog]`).
   - Стилизация: монохромная субтильная рамка `border-slate-200/80 dark:border-neutral-800`, моноширинный компактный шрифт, нейтральный фон без ярких неоновых подсветок.
2. Акцент на инженерных задачах в интерфейсе:
   - В карточке рекомендаций (Action Bar) явно выделить формат готовой задачи: заголовок тикета, приоритет (P0), компонент сбоя и конкретное исправление для спринта.
   - Добавить кнопку экспорта или копирования задачи в буфер обмена в формате Markdown / Linear Issue (`Copy as Linear Issue`).

## 3. Требования к коду, архитектуре и тестам

1. Чистота UI и стандарты верстки:
   - Стек шрифтов: Geist Sans / Inter.
   - Все числовые индикаторы, проценты и счетчики строго в `tabular-nums`.
   - Полное отсутствие смайликов и эмодзи в интерфейсе (использовать только строгие SVG-иконки).
2. Браузерные E2E тесты (Playwright):
   - Напиши или обнови E2E тест в `e2e/product-flow.spec.ts` для проверки сценария «Instant Preview»:
     - Клик по кнопке «Jonli namunani ko'rish».
     - Проверка видимости матрицы проблем и блока Action Bar без сетевых ошибок.
     - Проверка работы фильтрации P0/P1/P2.
   - Все тесты должны завершаться со статусом passed (4/4 или более).
3. Инструменты и окружение:
   - Сохраняй валидный статус Figma Bridge MCP.
   - Выполни валидацию сборки (`npm run build`) без ошибок линтера и TypeScript.

## 4. Поэтапный процесс исполнения (Workflow)

Этап 1: Реализация Instant Preview и UVP
- Обнови компоненты ввода и верхнего уровня (`src/components/feedback-input.tsx`, `src/app/page.tsx`, `src/components/results/summary-card.tsx`).
- Внедри эталонный набор данных для мгновенного рендеринга и кнопку «Copy as Linear Issue».

Этап 2: Тестирование Playwright
- Запусти локальные тесты: `npx playwright test`.
- Убедись, что все селекторы соответствуют обновленному интерфейсу.

Этап 3: Production Build и Vercel Deploy
- Выполни чистую сборку проекта: `npm run build`.
- Закоммить изменения с понятным сообщением (например, `feat(ui): add instant preview and linear issue export for portfolio evaluation`).
- Отправь изменения в `origin main` и верифицируй ответ production URL через HTTP 200 OK.
